Critical implementation rule: if a barcode is scanned repeatedly, the same reward must never be credited or redeemed twice. Expiry must be tracked per earning event, so a newly earned reward does not extend the expiry of older rewards.

## Flaws:

1. Weight does not directly determine a discount percentage. A conversion rule is still required, such as a weight-to-reward table or a formula.
2. Accumulated percentage discounts can become financially unsafe. For example, repeatedly adding 5% rewards could eventually produce an excessive discount. The maximum discount per purchase must eventually be defined.
3. Barcode and accumulated balance need separate responsibilities. A barcode should identify a reward event or customer account; it should not independently contain or control the reward balance.
4. Seven-day expiry needs event-level tracking. Each earning event must expire independently. Otherwise, new rewards could unintentionally extend older rewards.
5. Payment gateway selection is still unresolved. Payment verification and dispensing must not depend on a success message from the frontend.

## Fixes:

### Recommended reward logic

Use this model:

- Each successful disposal creates one reward event.
- Reward earned is calculated from the measured weight.
- Each event expires after seven days.
- Eligible, unexpired rewards contribute to the customer's accumulated balance.
- At checkout, the backend calculates the applicable discount.
- Once a purchase succeeds, the corresponding reward amount is deducted.
- Failed or cancelled payments must not consume rewards.

Keep these as separate values:

| Value                 | Purpose                             |
| --------------------- | ----------------------------------- |
| Disposal weight       | Input for reward calculation        |
| Reward percentage     | Percentage earned from a disposal   |
| Accumulated balance   | Customer's available rewards        |
| Discount per purchase | Amount applied at checkout          |
| Maximum discount      | Purchase-level restriction, pending |
